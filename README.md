# Mapping Log

ระบบบันทึกการวิ่งรถ Mapping สำหรับทีมวิศวกร รันบน **Cloudflare** (Workers + D1) และ deploy อัตโนมัติจาก **GitHub**

## ทำอะไรได้บ้าง

- **3 ภาษา: ไทย / English / 简体中文** — กดสลับได้ที่มุมขวาบน (หน้าล็อกอินด้วย) ระบบจำภาษาไว้ในเครื่อง ครั้งแรกเลือกตามภาษาของเบราว์เซอร์ ข้อความแจ้งเตือนจากเซิร์ฟเวอร์ ไฟล์ CSV สรุป และประวัติการทำงานก็เปลี่ยนตามภาษา
- **ใช้ง่ายบนมือถือ** — หน้าบันทึกภาคสนามมีปุ่มใหญ่ปุ่มเดียวด้านล่าง บอกขั้นต่อไปให้เสมอ (Calibration ก่อนวิ่ง → รอบ 1 → รอบ 2 … → Calibration หลังวิ่ง)
  - กันกดพลาด: ปุ่มจบรอบต้องแตะ 2 ครั้ง และแตะเบิ้ลโดยไม่ตั้งใจจะไม่ข้ามไปขั้นถัดไป
  - ถ้ารอบถูกเริ่มจากเครื่องอื่นและเครื่องนั้นยังส่ง GPS อยู่ ระบบจะเตือนก่อน ไม่ให้บันทึกซ้อนกันโดยไม่ตั้งใจ
- **ตรวจเส้นทางตาม SOP อัตโนมัติจาก GPS** (ไม่ต้องกดอะไรเพิ่ม) — ตามหลักการเก็บข้อมูลแผนที่: 1 รอบ = 1 วงปิด
  - **ไป–กลับครบทั้งสองฝั่ง** (≥ 80% ของเส้นทางมีทั้งขาไปและขากลับ — รองรับถนนที่มีเกาะกลางกว้างถึง ~60 ม.)
  - **ปิดวง**: จุดเริ่มกับจุดจบห่างกันไม่เกิน 100 ม.
  - **ไม่เกิน 3 ชม. ต่อรอบ** (เตือนเมื่อใกล้ครบ 2 ชม. 30 นาที)
  - แสดงสดระหว่างวิ่ง เตือนตอนกดจบรอบถ้ายังไม่ครบ และขึ้นเป็นเช็กลิสต์ให้ผู้ตรวจ QC (เป็นข้อแนะนำ ไม่บังคับ เพราะถนนทางเดียว/ถนนแคบวิ่งเที่ยวเดียวได้)
- **หน้าตาแบบเดียวกับเว็บ super-x.tech** — ฟอนต์ Poppins + Prompt (เก็บไฟล์ฟอนต์ไว้ในเว็บเอง ใช้ได้แม้ออฟไลน์) โทนสีกรมท่า/ฟ้า/เขียว
- **เริ่มงานใหม่เร็ว** — จำโปรเจกต์ / คนขับ / รถที่ใช้ล่าสุด ถ้ามีตัวเลือกเดียวเลือกให้อัตโนมัติ ไม่กรอกชื่องานระบบตั้งให้ กดปุ่มเดียวไปหน้าบันทึก
  - ไม่มีคนขับ / รถ / โปรเจกต์ที่ต้องการ กด **+ เพิ่มใหม่** ได้เลยในหน้านี้ (ชื่อซ้ำ ระบบเลือกรายการเดิมให้)
- **ข้อมูลหลัก (คนขับ / รถ / โปรเจกต์)** — ทุกบัญชียกเว้น "ดูอย่างเดียว" เพิ่ม แก้ไข และปิดใช้งานได้เองที่เมนู **ข้อมูลหลัก** ไม่ต้องรอผู้ดูแลระบบ ทุกรายการบอกว่าใครเพิ่ม เมื่อไร และทุกการแก้ไขบันทึกไว้ในประวัติการใช้งาน (ค่าเดิม → ค่าใหม่) — รายการที่อยู่ในงานที่ส่งแล้ว/ผ่าน QC แล้ว แก้ชื่อหรือรายละเอียดได้เฉพาะผู้ดูแลระบบ (ประวัติงานเก่าจะได้ไม่เปลี่ยนตาม)
- **ส่งงาน → QC ตรวจ (มีบันทึกทุกขั้น)** — ทีมภาคสนามกด **ส่งงานให้ QC ตรวจ** เมื่อทำครบ → ผู้ตรวจ QC กด **ผ่าน** (งานล็อก) หรือ **ตีกลับให้แก้** (ต้องบอกเหตุผล)
  - ทุกขั้นบันทึก **ชื่อคนทำ + วันเวลา + หมายเหตุ** แสดงเป็น "ประวัติการส่งงานและการตรวจ" ในหน้ารายละเอียดงาน หน้าแรก และไฟล์ CSV สรุป — มีปัญหาภายหลังตามหาคนรับผิดชอบได้
  - **คนส่งงานตรวจงานของตัวเองไม่ได้** ต้องให้ผู้ตรวจ QC คนอื่นตรวจ (ผู้ดูแลระบบก็เช่นกัน)
  - ส่งแล้วแก้ไข/บันทึกเพิ่มไม่ได้ จนกว่าคนส่งจะกด **ถอนการส่ง** (ก่อน QC ตรวจ) หรือ QC ตีกลับ — ข้อมูลที่ QC ตรวจจึงตรงกับที่ส่งมา
  - งานที่ผ่านแล้ว ถ้าพบปัญหา ผู้ตรวจ QC (ที่ไม่ใช่คนส่ง) กดยกเลิกผลผ่านและตีกลับได้ พร้อมเหตุผล
- **ล็อกอินและแบ่งสิทธิ์** — ผู้ดูแลระบบสร้างบัญชีให้ทีม ผู้ใช้ต้องเปลี่ยนรหัสผ่านตอนเข้าครั้งแรก ใส่รหัสผิด 5 ครั้งบัญชีจะถูกล็อก 15 นาที
- **ลายน้ำชื่อบัญชี (กันแคปหน้าจอ)** — ทุกหน้าหลังล็อกอินมีลายน้ำจาง ๆ เป็นชื่อ + ชื่อผู้ใช้ของบัญชีที่ล็อกอิน และวันเวลาปัจจุบัน (เวลาไทย อัปเดตทุกนาที) ทับทั้งหน้าจอรวมถึงแผนที่และตอนสั่งพิมพ์ ภาพที่แคปออกไปจึงรู้ว่ามาจากบัญชีไหน เมื่อไร (ไม่บังการกดปุ่ม) — เว็บห้ามแคปหน้าจอไม่ได้จริง ลายน้ำมีไว้ให้ตามย้อนกลับได้
- **Calibration ทุกวัน** — บันทึกเวลาเริ่มและเวลาเสร็จสิ้น (ชม.:นาที) ได้หลายครั้งต่อวัน (ก่อนวิ่ง / ระหว่างวัน / หลังวิ่ง)
  - กดปุ่มเริ่ม/เสร็จสิ้นตอนทำจริง หรือกรอกเวลาเองถ้าลืมกด
  - ถ้ายังไม่มี Calibration ที่ครบทั้งเวลาเริ่มและเสร็จ (หรือยังมี Calibration ที่ค้างไม่ได้กดเสร็จสิ้น) งานจะขึ้นเตือน และ **ยังส่งงานให้ QC ไม่ได้**
- **บันทึก GPS จากมือถือ** ผ่านเบราว์เซอร์ (ไม่ต้องลงแอป)
  - เน็ตหลุดไม่เสียข้อมูล: เก็บในเครื่องก่อนแล้วส่งเองเมื่อมีสัญญาณ (ส่งซ้ำได้โดยไม่เกิดข้อมูลซ้ำ)
  - ถ้างานถูกส่งให้ QC (จากเครื่องอื่น) ระหว่างที่มือถือยังมีข้อมูลค้าง ข้อมูลไม่หาย — เก็บไว้ในเครื่อง (ป้าย "ค้างส่ง") แล้วส่งให้เองเมื่อถอนการส่งหรือถูกตีกลับ
  - รีเฟรชหน้าหรือเผลอปิดแท็บ เปิดกลับมาก็บันทึกรอบเดิมต่อได้ทันที
  - ตัดจุดที่คลาดเคลื่อนเกิน 50 ม. และไม่เก็บจุดซ้ำตอนจอดนิ่ง
  - เพิ่มลงหน้าจอโฮมได้ (PWA) และเปิดหน้าแอปได้แม้ไม่มีสัญญาณ
- **แบ่งรอบหรือไม่แบ่งก็ได้** — ถ้าแบ่ง ต้องใส่หัวข้อการเก็บ และเวลาเริ่ม–จบตามแผนของทุกรอบ ระบบเทียบเวลาจริงกับแผนให้ (ช้า/เร็วกี่นาที) รองรับงานกะกลางคืนที่ข้ามเที่ยงคืน
- **ดูย้อนหลัง** — กรองตามวันที่ / โปรเจกต์ / คนขับ / รถ / สถานะงาน (กำลังทำ / รอตรวจ / ผ่าน QC / ตีกลับ) / Calibration ดูแผนที่แยกสีตามรอบ และกดเล่นเส้นทางย้อนหลังได้
- **ตรวจสอบได้** — ประวัติการทำงานของทุกงาน (ใครทำอะไร เมื่อไหร่) รวมถึงค่าเดิม→ค่าใหม่ของการแก้ไข Calibration งานที่ส่งแล้วหรือผ่าน QC แล้วจะถูกล็อก
- **Export** — GPX, GeoJSON (เปิดใน QGIS / Google Earth ได้), CSV รายจุด และ CSV สรุปหลายงานสำหรับทำรายงาน

## ติดตั้งบน Cloudflare ผ่าน GitHub (ทำครั้งเดียว)

สิ่งที่ต้องมี: บัญชี Cloudflare (เริ่มจากแผนฟรีได้), บัญชี GitHub และ Node.js 22 ในเครื่อง (ใช้ในขั้นตอนที่ 1)

### 1. สร้างฐานข้อมูล D1

ในโฟลเดอร์โปรเจกต์ รัน:

```bash
npm install
npx wrangler login
npx wrangler d1 create mapping-log --location apac
```

คำสั่งจะแสดง `database_id` ออกมา ให้คัดลอกไปใส่ในช่อง `database_id` ในไฟล์ `wrangler.jsonc`
(ไฟล์ในชุดนี้ใส่ database_id ของ mapping-log ที่ใช้อยู่ไว้แล้ว ถ้าสร้างฐานข้อมูลใหม่ให้เปลี่ยนเป็นของใหม่)

> ไม่อยากใช้คำสั่ง: เข้า Cloudflare Dashboard → **Storage & Databases → D1 SQL Database → Create** ตั้งชื่อ `mapping-log` เลือก Location เป็น Asia-Pacific แล้วคัดลอก Database ID มาใส่ใน `wrangler.jsonc` เหมือนกัน

### 2. สร้าง API Token และหา Account ID

1. Cloudflare Dashboard → หน้า **API Tokens** (เมนู Manage Account → Account API Tokens หรือ My Profile → API Tokens) → **Create Token**
2. เลือก template **Edit Cloudflare Workers**
3. ตรวจว่ามีสิทธิ์ **Account → D1 → Edit** ถ้าไม่มีให้กด Add more เพิ่มเข้าไป
4. จำกัด Account Resources ให้เป็นบัญชีของคุณบัญชีเดียว → Create Token → คัดลอก token เก็บไว้ (จะแสดงครั้งเดียว)
5. **Account ID** ดูได้จากหน้า Workers & Pages (แถบด้านขวา)

### 3. สร้าง repository บน GitHub และตั้ง Secrets

1. สร้าง repository ใหม่ (แนะนำแบบ Private)
2. ไปที่ **Settings → Secrets and variables → Actions → New repository secret** แล้วเพิ่ม 2 ค่า
   - `CLOUDFLARE_API_TOKEN` = token จากขั้นตอนที่ 2
   - `CLOUDFLARE_ACCOUNT_ID` = Account ID

### 4. Push โค้ดขึ้น GitHub

```bash
git init
git add .
git commit -m "Mapping Log"
git branch -M main
git remote add origin https://github.com/<ชื่อองค์กร>/<ชื่อ repo>.git
git push -u origin main
```

GitHub Actions จะทำงานเอง (ดูได้ที่แท็บ **Actions**): ตรวจโค้ด → build → อัปเดตฐานข้อมูล D1 → deploy

เมื่อเสร็จ เว็บจะอยู่ที่ `https://mapping-log.<subdomain ของคุณ>.workers.dev`
(ถ้าเพิ่งใช้ Workers ครั้งแรก Cloudflare อาจให้ตั้งชื่อ subdomain ของ workers.dev ก่อน ที่หน้า Workers & Pages)

> หลังจากนี้ ทุกครั้งที่ push เข้า `main` ระบบจะ deploy ให้อัตโนมัติ ส่วน Pull Request จะแค่ตรวจโค้ดและ build (ไม่ deploy)

### 5. ตั้งค่า SETUP_KEY (รหัสสำหรับสร้างผู้ดูแลระบบคนแรก)

Cloudflare Dashboard → **Workers & Pages → mapping-log → Settings → Variables and Secrets → Add**
→ Type: **Secret**, Name: `SETUP_KEY`, Value: ตั้งรหัสยาว ๆ ที่เดายาก → Deploy

(หรือใช้คำสั่ง `npx wrangler secret put SETUP_KEY`)

### 6. สร้างผู้ดูแลระบบคนแรก

เปิดเว็บ → ระบบจะพาไปหน้า **ตั้งค่าระบบครั้งแรก** → ใส่ SETUP_KEY และสร้างบัญชีผู้ดูแลระบบ
(หน้านี้ใช้ได้ครั้งเดียว เมื่อมีผู้ใช้คนแรกแล้วจะปิดถาวร)

### 7. ตั้งค่าเริ่มต้นในระบบ

- เมนู **จัดการระบบ → ผู้ใช้งาน** — สร้างบัญชีให้ทีม (ระบบสุ่มรหัสชั่วคราวให้ ผู้ใช้ต้องเปลี่ยนรหัสตอนเข้าครั้งแรก)
- เมนู **ข้อมูลหลัก** — เพิ่มคนขับ / รถ / โปรเจกต์ (ทีมภาคสนามเพิ่มเองได้ หรือกด "+ เพิ่มใหม่" ตอนเริ่มงาน)

### (ไม่บังคับ) ใช้โดเมนของบริษัท

Workers & Pages → mapping-log → Settings → **Domains & Routes → Add → Custom domain** (โดเมนต้องอยู่ใน Cloudflare)

## วิธีใช้งานในภาคสนาม

1. **เริ่มงานใหม่** — หน้าแรกกดปุ่มเขียว **＋ เริ่มงานใหม่** → แตะเลือกโปรเจกต์ คนขับ รถ (ระบบจำค่าล่าสุดไว้ให้) → ถ้าแบ่งรอบ ให้เปิดสวิตช์ **แบ่งรอบ** แล้วใส่หัวข้อและเวลาตามแผน → กด **▶ สร้างงานและเริ่มบันทึก**
2. **ทำตามปุ่มใหญ่ด้านล่าง** — ปุ่มจะเปลี่ยนเป็นขั้นต่อไปเองทุกครั้ง
   - **▶ เริ่ม Calibration ก่อนวิ่ง** → ทำ Calibration (มีตัวจับเวลา) → **■ เสร็จสิ้น Calibration**
   - **▶ เริ่มรอบ 1** → วิ่งเก็บข้อมูล (เปิดหน้าจอค้างไว้) → **■ จบรอบ 1** แล้ว **แตะอีกครั้งเพื่อยืนยัน**
   - ทำต่อรอบถัดไปจนครบ → **▶ เริ่ม Calibration หลังวิ่ง** (หรือกด "จบงานโดยไม่ทำ Calibration หลังวิ่ง")
   - อยากวิ่งรอบอื่นก่อน: แตะชื่อรอบในรายการ "ขั้นตอนงานนี้" · ลืมกดปุ่ม Calibration: "กรอกเวลาเอง" · เพิ่มรอบ / Calibration ระหว่างวัน / ซ่อนแผนที่: ปุ่ม **⋯** มุมขวาบน
3. **งานวันนี้** — หน้าแรกแสดงงานของวันนี้พร้อมปุ่ม **▶ ทำต่อ** (เผลอปิดหน้า กลับมากดปุ่มนี้ได้เลย)
4. **ส่งงาน** — ทำครบทุกขั้นแล้ว ปุ่มใหญ่จะเป็น **ส่งงานให้ QC ตรวจ** (แตะ 2 ครั้ง ใส่หมายเหตุถึงผู้ตรวจได้) ต้องต่อเน็ตและส่งข้อมูล GPS ในเครื่องครบก่อน — ส่งแล้วแก้ไม่ได้ ถ้ากดผิดให้กด **ถอนการส่ง** (ได้ก่อน QC ตรวจ)
5. **QC** — ผู้ตรวจเปิดรายละเอียดงาน ตรวจเส้นทาง/เวลา แล้วกด **✓ ผ่าน QC** หรือ **↩ ตีกลับให้แก้** (ต้องใส่เหตุผล) ทีมภาคสนามจะเห็นเหตุผลในหน้าบันทึก แก้แล้วกดส่งใหม่ได้ หน้าแรกมีปุ่มกรองเร็ว "รอตรวจ QC / ถูกตีกลับ / ไม่มี Calibration"

**คำแนะนำสำหรับมือถือ**
- เปิดเว็บด้วย Chrome (Android) หรือ Safari (iPhone) แล้วกด **เพิ่มลงหน้าจอโฮม** จะใช้เหมือนแอป
- อนุญาตให้เว็บใช้ **ตำแหน่ง (Location)** และตั้งเป็นความแม่นยำสูง
- **เปิดหน้าจอค้างไว้ระหว่างวิ่ง** เพราะมือถือ (โดยเฉพาะ iPhone) จะหยุดส่ง GPS ให้เว็บเมื่อปิดจอหรือสลับไปแอปอื่น ระบบพยายามกันจอดับให้อัตโนมัติถ้าเครื่องรองรับ
- ถ้าเน็ตหลุด บันทึกต่อได้ตามปกติ ป้าย ☁ ด้านบนจะบอกว่ามีข้อมูล "รอส่ง" กี่รายการ (แตะเพื่อดูรายละเอียด)
- ป้าย GPS สีเขียว = แม่นยำดี (±20 ม.) / เหลือง = พอใช้ / แดง = คลาดเคลื่อนเกิน 50 ม. (จุดนั้นจะไม่ถูกบันทึก)
- ระหว่างวิ่งดูป้าย SOP ในกรอบ "กำลังบันทึก": **⇄ ไป–กลับ %** (ต้องวิ่งกลับทางเดิมอีกฝั่งให้ครบ), **⟲ ห่างจุดเริ่ม** (กลับมาจบที่จุดเริ่ม), **⏱ เวลา / 3 ชม.**

## ค่าใช้จ่ายและขีดจำกัดของ Cloudflare

| | แผนฟรี | Workers Paid ($5/เดือน) |
|---|---|---|
| D1 แถวที่เขียน | 100,000 แถว/วัน | 50 ล้านแถว/เดือน |
| D1 แถวที่อ่าน | 5 ล้านแถว/วัน | 25,000 ล้านแถว/เดือน |
| ขนาดฐานข้อมูล | 500 MB ต่อฐานข้อมูล | 10 GB ต่อฐานข้อมูล |
| คำขอ Worker (API) | 100,000 ครั้ง/วัน | 10 ล้านครั้ง/เดือน (เกินคิดเพิ่ม) |
| CPU ต่อคำขอ | 10 ms | ค่าเริ่มต้น 30 วินาที |
| ไฟล์หน้าเว็บ (static) | ฟรีไม่จำกัด | ฟรีไม่จำกัด |

ประมาณการการใช้งาน (รถ 1 คัน วิ่ง 8 ชม./วัน ส่งข้อมูลทุก ~10 วินาที):
- เขียน D1 ประมาณ 9,000 แถว/วัน → แผนฟรีรองรับได้ราว **10 คัน-วัน ต่อวัน**
- พื้นที่ประมาณ 1–2 MB/คัน/วัน → แผนฟรี (500 MB) เก็บได้ราว 300 คัน-วัน

**แนะนำ:** ทดลองด้วยแผนฟรีได้ แต่เมื่อใช้งานจริงต่อเนื่องหลายคัน ควรอัปเกรดเป็น **Workers Paid ($5/เดือน)**
(ราคาและขีดจำกัด ณ ต.ค. 2569 — ตรวจสอบล่าสุดที่ https://developers.cloudflare.com/d1/platform/pricing/)

> **หมายเหตุแผนฟรี:** การล็อกอินใช้การเข้ารหัส PBKDF2 ซึ่งใช้ CPU ราว 20 ms ต่อครั้ง (เกิน 10 ms ของแผนฟรี) Cloudflare ยอมให้เกินเป็นครั้งคราวได้ แต่ถ้าล็อกอินแล้วเจอ Error 1102 บ่อย ให้อัปเกรดแผน หรือเพิ่มตัวแปร `PBKDF2_ITERATIONS` = `50000` (ใน Variables and Secrets) แล้วตั้งรหัสผ่านใหม่ให้ผู้ใช้

## สำรองข้อมูล

- **D1 Time Travel**: ย้อนฐานข้อมูลกลับไปเวลาใดก็ได้ใน 7 วัน (แผนฟรี) / 30 วัน (แผน Paid)
  `npx wrangler d1 time-travel restore mapping-log --timestamp=<เวลา>`
- **Export ทั้งฐานข้อมูล**: `npx wrangler d1 export mapping-log --remote --output=backup.sql`
- รายงาน: กด Export สรุป (CSV) ที่หน้าประวัติงาน หรือ GPX / GeoJSON / CSV ที่หน้ารายละเอียดงาน

## ความปลอดภัย

- รหัสผ่านเข้ารหัสแบบ PBKDF2-SHA256 (100,000 รอบ + salt) ไม่เก็บรหัสจริง
- Session เป็น cookie แบบ HttpOnly / Secure / SameSite อายุ 30 วัน (ต่ออายุอัตโนมัติเมื่อใช้งาน) ฐานข้อมูลเก็บเฉพาะค่า hash ของ token
- ล็อกบัญชี 15 นาทีเมื่อใส่รหัสผิด 5 ครั้ง, บังคับเปลี่ยนรหัสเมื่อได้รหัสชั่วคราว, เปลี่ยนรหัสแล้วเครื่องอื่นถูกออกจากระบบ
- ตรวจสิทธิ์ที่ฝั่ง Worker ทุก API (ไม่พึ่งการซ่อนปุ่มในหน้าเว็บ)
- กัน CSRF (SameSite cookie + ตรวจ Origin) และตั้ง Security headers / Content-Security-Policy (`public/_headers`)
- ประวัติการใช้งานทั้งระบบ (ล็อกอิน, ผู้ใช้, ข้อมูลหลัก, งาน) ดูได้ที่ จัดการระบบ → ประวัติการใช้งาน

## สำหรับนักพัฒนา

### รันในเครื่อง

```bash
npm install
cp .dev.vars.example .dev.vars      # SETUP_KEY=dev-setup-key
npm run db:migrate:local            # สร้างตารางในฐานข้อมูล local
npm run dev                         # http://localhost:5173
```

- ทดสอบแบบ production ในเครื่อง: `npm run build && npm run preview`
- ทดสอบ GPS บนมือถือจริง: ต้องเป็น HTTPS — ใช้ URL `workers.dev` หลัง deploy จะง่ายที่สุด
- ตรวจโค้ด: `npm run typecheck`

### แก้โครงสร้างฐานข้อมูล

สร้างไฟล์ migration ใหม่ (ห้ามแก้ไฟล์เดิมที่ deploy ไปแล้ว):

```bash
npx wrangler d1 migrations create mapping-log add_something
# แก้ไฟล์ SQL ใน migrations/ แล้วทดสอบ
npm run db:migrate:local
```

เมื่อ push เข้า `main` GitHub Actions จะรัน migration บน D1 จริงให้ก่อน deploy

### ข้อจำกัดที่ควรรู้

- เบราว์เซอร์บนมือถือไม่ส่ง GPS เบื้องหลัง ถ้าต้องการบันทึกขณะปิดจอจริง ๆ ต้องทำเป็นแอป native หรือใช้เครื่อง GPS logger แล้วนำไฟล์มาเข้าระบบ
- แผนที่ใช้ OpenStreetMap ซึ่งเหมาะกับทีมขนาดเล็ก ถ้าใช้งานหนักควรเปลี่ยนไปใช้ผู้ให้บริการแผนที่ (เช่น MapTiler) ตามนโยบายการใช้งานของ OSM
- ค่ากรองความแม่นยำ GPS (50 ม.) ปรับได้ที่ `MAX_ACCURACY_M` ใน `src/lib/recorder.ts`
- เกณฑ์ตรวจ SOP (80% ไป–กลับ, ปิดวง 100 ม., 3 ชม., รัศมีหาเที่ยวสวนทาง 60 ม.) ปรับได้ที่ `SOP` ใน `src/lib/sop.ts`
